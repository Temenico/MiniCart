# 🧩 HU-05 - Configurar el API Gateway y enrutar las solicitudes al microservicio

## 📌 Ficha de la historia

- **Título:** Configurar el API Gateway y enrutar las solicitudes al microservicio
- **ID:** HU-05
- **Prioridad:** Must Have (Alta)
- **Rama de desarrollo:** `HU-05-dev`
- **Rama de QA:** `HU-05-qa`

## 👤 Historia de usuario

Como **equipo de desarrollo**,
quiero **configurar el API Gateway como punto de entrada del sistema**,
para **centralizar las solicitudes del frontend hacia el microservicio**.

## 📖 Descripción

Esta historia implementa y configura `api-gateway` para enrutar las solicitudes del frontend hacia `cart-service`.

Se definen rutas para productos y carritos, dejando al gateway como punto de acceso central entre frontend y microservicio.

## ✅ Criterios de aceptación

- [x] Existe el proyecto `api-gateway`.
- [x] El gateway inicia con configuración mínima funcional.
- [x] Se configuran rutas para productos.
- [x] Se configuran rutas para carritos.
- [x] Las solicitudes del frontend pasan por el gateway.
- [x] El microservicio responde correctamente a través del gateway.
- [x] No existe lógica de negocio dentro del gateway.

## 📦 Entregables esperados

- Proyecto `api-gateway`.
- Configuración de rutas.
- Integración con `cart-service`.
- Validación de acceso desde el gateway.

## 🏁 Definición de terminado

La historia termina cuando el API Gateway funciona como punto de entrada único y enruta correctamente las solicitudes hacia `cart-service`.

## ✅ Qué se hizo

- Se configuraron rutas explícitas de gateway para productos:
  - `/api/products`
  - `/api/products/**`
- Se configuraron rutas explícitas de gateway para carritos:
  - `/api/carts`
  - `/api/carts/**`
- Se aplicó `StripPrefix=1` para reenviar solicitudes con path compatible hacia `cart-service`.
- Se parametrizó la URL del microservicio con:
  - `CART_SERVICE_URL` (default: `http://localhost:8091`)
- Se agregó configuración CORS para frontend local:
  - `http://localhost:5273`
- Se actualizó documentación del módulo en:
  - `api-gateway/README.md`

## 🚫 Qué no se hizo

- No se implementó lógica de negocio dentro del gateway.
- No se implementó frontend completo consumiendo gateway (corresponde a HU-06 y HU-07).
- No se implementó cierre de integración final de despliegue (corresponde a HU-08).

## 🔜 Qué se va a hacer

- Continuar con HU-07 para frontend de carritos.
- Consolidar integración end-to-end final en HU-08.
